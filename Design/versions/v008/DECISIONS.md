Ця ітерація змінює лише `Design/`. SwiftUI, SwiftData, генератор, каталоги продуктів, медіа та seed stores залишаються на попередньому стані. Перенесення в застосунки — після рев’ю. v000–v007 захищені контрольними сумами та не перезаписані.

## Синхронізація з застосунками

База — вихідний код `95a5ca5`:

- `SessionBuilderView`: тип зафіксовано вже на екрані вибору способу створення; перемикача немає ні в новому, ні в існуючому редакторі. Ручне створення одразу відкриває список вправ.
- `SettingsView` / `AppConfiguration`: дія «Оцінити застосунок» із поточним product-specific посиланням на App Store.
- Каталог і переклади взяті з актуальних seed inputs, `ExerciseLocalizationCatalog` і `Localizable.xcstrings`. У v008 застосовано **лише демонстраційне** вилучення 8 / 2 вправ із наданого плану; у бібліотеці 91 / 103 вправи. Архівна історія зберігається.
- Палітра, фіксована типографіка, системні вкладки, центровані заголовки, скляні кнопки та поточна форма активного заняття успадковані від v007. HTML лише наближує нативне скло.

## Рішення для рев’ю

| Сценарій | Запропонований інтерфейс |
|---|---|
| Створення | Спосіб → м’язи → час і рівень → необов’язкові умови → денний варіант → збереження. |
| Час | 15 / 30 / 45 / 60 хв; пояснення про підходи, відпочинок і переходи. Розминка поза цим часом. В огляді окремо показані оцінка й обраний бюджет. |
| Рівень | Три рівні; збережений рівень стає початковим для наступного створення. Скасування налаштувань відновлює попередні значення. |
| OnlyBody | Без підтвердженого обладнання — тільки вправи без нього. Повний перелік доступності відкривається в окремій панелі. |
| OnlyWeights | Типово звичайний зал; уточнення обладнання необов’язкове. Уточнений список можна скасувати або застосувати. |
| Обмеження | Сім ділянок → явний вибір небажаних навантажень → застосування. Вибір ділянки сам не вмикає жодного обмеження. |
| Головний екран | Smart-картка бере участь у тому самому групуванні за розкладом: Today у запланований день, решта тренувань — в іншій секції. День визначається локально й враховує демонстраційний перехід дати. |
| Денний варіант | Дата, рівень, оцінка часу, основні / допоміжні вправи, підходи, повторення, відпочинок і основні м’язи. Односторонні повторення позначені «на кожний бік», Bear Crawl — повними циклами. |
| Зміна дня | Кнопка **Smart · Наступний день** у панелі переглядача. Основні вправи утримуються за однакових умов; допоміжні можуть змінитися. Новизна не гарантована. |
| Заміна | Причина «Немає обладнання / не можу знайти» або «Хочу іншу вправу», далі варіанти заміни. Звичайна заміна діє на одне заняття. |
| Постійне виключення | Окрема дія з підтвердженням. Виключення видно в умовах тренування; його можна повернути. |
| Ручний конфлікт | Конфліктні альтернативи приховані за окремою дією. Перед вибором показано конкретне навантаження й підтвердження лише для цієї заміни. Інші фільтри не скидаються. |
| Непокриті потреби | Окремий блок із відсутніми рухами / групами та дією зміни умов. Збереження / старт неповного варіанта заблоковано — це UX-пропозиція для погодження. |
| Старт | У сесію передається саме переглянутий список; вага починається з 0. Після старту зміна демонстраційної дати не перебудовує заняття. |
| Назва й розклад | Окрема панель із транзакційним застосуванням. Розклад не впливає на локальний ключ денного варіанта. |

## Межі прототипу

- У браузері є **один репрезентативний Smart-шаблон на продукт**. Нове збереження замінює цей демонстраційний шаблон; це не пропозиція обмежувати кількість тренувань у застосунку. Ручні тренування використовують попередні тимчасові fixtures.
- Smart-шаблон, рівень, денні варіанти та явні виключення зберігаються у `localStorage` з префіксом `only-smart-v008:`. «Скинути демодані» очищає лише цей простір. Особисті дані телефона не читаються. Активна сесія не відновлюється після перезавантаження сторінки.
- Невеликий генератор у `smart.js` працює з **18 / 20 явними прикладами** в `smart-data.js`, а не зі всіма 194 вправами. Нерозмічені вправи не допускаються до демонстраційного Smart. Бібліотека містить повні запропоновані 91 / 103 вправи. Відсутність кандидата в демонаборі не доводить відсутності відповідної вправи в повному каталозі.
- Для демонстрації використано явну таблицю: основні — 3 підходи (4 на advanced), 10 повторень beginner / 8 решта, 90 с відпочинку; допоміжні — 2 підходи beginner / 3 решта, 12 повторень, 60 с відпочинку. Оцінка: 3 с на повторення, обидва боки для односторонніх рухів, 30 с переходу. Це **не погоджена таблиця тренувальних рекомендацій**.
- Бюджет у демо не перевищується, але повний алгоритм скорочення обсягу, клінічно перевірені правила навантажень, 194 метадані, сумісність старих сховищ і нові репозиторії — майбутня нативна робота за вихідним планом.
- Усі п’ять навантажень показані для кожної ділянки: медичну відповідність «ділянка → рекомендовані виключення» тут навмисно не закладено. Очікується таблиця правил і джерел від користувача. Теги fixtures лише демонструють поведінку підтвердження та конфлікту; це не оцінка безпечності вправ.
- Відео-ID, автори, стартові зміщення й плеєр не змінені. Історичний HTML-плеєр лишився симуляцією. Нові відео не додавалися; медіарев’ю не виконувалося й не заявляється.

## Перевірка

Запустити локальний сервер за інструкцією `Design/README.md`, потім із кореня, з доступним host Playwright та Google Chrome:

```sh
node Design/tests/verify-v008.cjs
node Design/tests/verify-v008-smart.cjs
node Design/tests/verify-v008-schedule.cjs
```

Результат 06.11.2026: **PASS** — 630 комбінацій екранів, 120 успадкованих і 240 Smart-панелей; обидва продукти × 5 мов × 3 ширини. Наскрізні сценарії створення, збереження/перезавантаження, скасування, замін, постійного виключення, конфлікту та завершення — PASS. 112 файлів історичних версій зберегли контрольні суми.

Звіти: `verification.json` та `smart-verification.json`. Перший перевіряє основні екрани, успадковані сценарії, палітру, зони натискання, порівняння версій і контрольні суми історії. Другий — Smart-переходи, локальне збереження, обладнання, обмеження, заміни, зміну дня й нові панелі в п’яти мовах на трьох ширинах для обох продуктів. Знімки — локальні, gitignored.

Нативні тести й `validate.sh full` для цієї HTML-ітерації не запускалися. Браузерні результати не підтверджують SwiftData, VoiceOver, реальний iPhone або роботу майбутнього нативного генератора.

Уточнення після рев’ю: Smart-картка інтегрована у спільні секції розкладу; кнопка — Start. `schedule-verification.json`: PASS для обох продуктів — запланований/незапланований день, редагування й перезавантаження розкладу, тільки Smart на сьогодні, день відпочинку та порожній сценарій.
