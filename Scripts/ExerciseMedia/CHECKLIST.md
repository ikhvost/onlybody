# Обов’язкова перевірка YouTube-відео

Застосовується до **OnlyBody та OnlyWeights**. Перевіряти **перед кожним додаванням або заміною відео**, зміною ID, автора чи стартової позиції, а також після змін плеєра й перед релізом. Заповнювати запис у `Reviews/<YYYY-MM-DD>/`, посилатися на нього в описі зміни. Генерація Swift-каталогу та зелені тести самі по собі не означають проходження цього чекліста.

Статуси: `PASS` — перевірено з доказом; `FAIL` — виявлена невідповідність; `UNCONFIRMED` — доказу немає; `N/A` — не застосовується з поясненням. Не позначати неперевірене як виконане. Старий браузерний огляд не є перевіркою ліцензії, повного звуку або фізичного iPhone. Невирішені пункти записувати явно; нове відео не оголошувати повністю перевіреним до їх закриття.

## Ліцензія та авторські права

- [ ] **L1. Тип ліцензії.** Розгорнути опис. Записати явно показану Standard YouTube License або Creative Commons Attribution і джерело підтвердження. Якщо тип не показаний — `UNCONFIRMED`, без вигаданого висновку. Standard є стандартним налаштуванням YouTube, але відсутність позначки CC не доводить налаштування конкретного відео.
- [ ] **L2. Походження.** Перевірити канал, опис автора, брендинг і зв’язок з офіційним сайтом/профілем; зберегти посилання та пояснення. Уникати очевидних перезаливів. Назва каналу або значок verified самі по собі не доводять права на кожен матеріал.
- [ ] **L3. Сторонні матеріали.** Переглянути весь ролик зі звуком; перевірити згадки про музику, нарізки та кредити. Зафіксувати сумнівні фрагменти з таймкодами. Не стверджувати наявність чи відсутність прав на музику лише за її звучанням; очевидно неправомірний контент не додавати.
- [ ] **L4. Докази.** Зберегти URL, ID, точну назву відео, автора, URL каналу, тип/статус ліцензії, дату перевірки, рецензента, скриншот сторінки та джерела висновків. Скриншот загальної сторінки не підміняє скриншот ліцензії.

**Вбудовування і повторне використання файлу — різні сценарії.** Для звичайного офіційного вбудовування не вимагати автоматично CC BY, купівлю ліцензії або індивідуальний лист автора. Standard-відео може бути придатним за дозволеного embed і дотримання умов YouTube. Доступний embed не надає права витягувати, змінювати чи перевидавати файл і не гарантує відсутності порушень у завантажувача. Для використання поза плеєром перевіряти окрему правову підставу. Якщо покладаємося саме на CC BY, виконати її атрибуційні умови.

## Відтворення у застосунку

- [ ] **P1. Embed і iPhone.** Відкрити Share → Embed, зберегти скриншот і перевірити живе відтворення в застосунку на фізичному iPhone. Записати модель, iOS, версію/коміт апки, продукт, дату, результат і мережу. Наявність кнопки Embed, браузерне відтворення, симулятор і локальна UI-fixture — різні докази; не підміняти ними тест на пристрої.
- [ ] **P2. Офіційний плеєр.** Використовувати YouTube IFrame Player API в `WKWebView`. Не витягувати URL відеопотоку й не відтворювати його власним плеєром.
- [ ] **P3. Ідентифікація.** Передавати app identity через HTTP Referer рекомендованим способом: `loadHTMLString(..., baseURL: URL(string: "https://<actual Bundle ID>"))`; задавати відповідний `origin` та не прибирати Referer. Поточні значення: `https://ikhvost.onlybody`, `https://ikhvost.onlyweights`. Приклад `com.onlyweights.app` не є Bundle ID цього репозиторію. Перевірити фактичне відтворення та відсутність помилки 153; `origin` сам по собі не заміняє Referer.
- [ ] **P4. Розмір.** Viewport плеєра не менший за 200 × 200 CSS px, контролери повністю доступні. Перевірити вузький екран і орієнтації; SwiftUI points і фізичні пікселі не змішувати.
- [ ] **P5. Цілісність YouTube.** Не приховувати, не обрізати й не перекривати рекламу, логотип, посилання та стандартні елементи керування. Не фільтрувати рекламні запити. Відсутність реклами під час одного тесту не підтверджує її блокування або показ для всіх користувачів.
- [ ] **P6. Джерело.** Зберегти атрибуцію й посилання стандартного плеєра та наявний підпис `Video by …`; не видавати контент за власний. Окремий підпис автора — правило цього проєкту, а не твердження про універсальну вимогу до всіх iframe-вбудовувань.
- [ ] **P7. Без офлайн-копій.** Не завантажувати, не кешувати й не зберігати відеофайли для офлайн-відтворення без відповідних дозволів. Звичайна мережева буферизація офіційного плеєра не є функцією офлайн-завантаження. Не вимикати потрібні механізми YouTube під приводом цього правила.
- [ ] **P8. Помилки.** Перевірити 100 (видалене/приватне), 101/150 (заборонений embed), 153 (ідентифікація), недоступну мережу та таймаут. Показати зрозумілий стан і повторну спробу; деталі вправи й тренування мають працювати далі. Відсутність демонстрації — допустимий стан OnlyWeights.

## Монетизація та App Store

- [ ] **A1. Без плати за перегляд.** Не продавати доступ до embedded YouTube-відео й не закривати його окремим paywall. Повторно перевірити цей пункт при додаванні покупок або підписок.
- [ ] **A2. Приватність і умови.** Доступна користувачеві політика має описувати YouTube API Services, передавання мережевих/технічних даних, сторонній контент/рекламу й можливі cookies, містити посилання на Google Privacy Policy. Додати доступні умови використання з YouTube Terms of Service та потрібний механізм ознайомлення/згоди. Перевірити вимоги YouTube III.A та Apple 5.1; локальний draft не означає опубліковану політику. `nonPersistent()` не означає відсутність передавання даних. Перевіряти момент першого мережевого запиту, а не лише натискання Play.
- [ ] **A3. Пакет для App Review.** Зберігати опис інтеграції, офіційні джерела правил з датою, докази embed, реєстр відео й результати тестів. За наявності окремого дозволу — його копію або контрольоване посилання. Не називати скриншот ліцензійним договором або гарантією схвалення Apple.

## Короткий технічний контроль: 8 пунктів

1. P2 — офіційний IFrame Player у WKWebView.
2. P3 — правильний Referer фактичного продукту.
3. P4 — мінімум 200 × 200.
4. P5/P6 — збережені реклама, брендинг, контролери та джерело.
5. P7 — немає завантаження/офлайн-копій.
6. A1 — немає paywall за YouTube-перегляд.
7. P8 — оброблені 100, 101, 150, 153.
8. A2 — YouTube враховано в доступній політиці приватності та умовах.

## Формат запису і порядок роботи

1. Створити запис для кожного нового/зміненого відео до зміни каталогу. Зберігати докази поза app targets у `Scripts/ExerciseMedia/Reviews/<date>/`; не додавати відеофайли, cookies, токени чи персональні дані пристрою.
2. Записати всі L/P/A-пункти зі статусами й посиланнями на докази. Спільну перевірку коду можна винести в один звіт із зазначенням коміту, але P1/L1–L4 стосуються конкретного відео. Для P1 записати, чи перевірено лише відкриття, старт або повний перегляд.
3. Невідомий тип ліцензії не прирівнювати до забороненого embed, але чесно лишити L1 непідтвердженим. FAIL щодо піратського походження, забороненого embed чи технічних вимог — не додавати відео до виправлення. Пакет з відкритими пунктами не називати повністю готовим до App Review.
4. Після перевірки оновити авторинг-каталог, згенерувати Swift і запустити `generate.py --check` для продукту. Для змін інтеграції запустити спільні `YouTubeIntegrationTests` обох schemes та OnlyBody `ExerciseDemonstrationTests` / `MovementDemonstrationTests`.
5. Перед релізом повторити доступність і embed, перевірити політику та покупки. Старі докази зберігати як історичні, а не перезаписувати датою нового непроведеного огляду.
