onlybody.app — сайт у спільному репозиторії

Сайт підготовлений локально й ще не опублікований. Публікується лише Website/dist.
Під час перевірки 26.10.2026 домен onlybody.app повертав Cloudflare 525.
Налаштування домену та HTTPS потрібно завершити на етапі публікації.
Немає npm, генератора, JavaScript, зовнішніх шрифтів, форм або аналітики.
Редагуйте HTML та CSS безпосередньо. assets/site.css зберігає спільні та юридичні
стилі; assets/marketing.css підключається лише на головній сторінці.
Іконки, справжні скриншоти з демонстраційними даними та карти м’язів узято
з власних застосунків. Походження ресурсів: Website/ASSETS.uk.txt.

CLOUDFLARE PAGES: РЕКОМЕНДОВАНЕ ПІДКЛЮЧЕННЯ ДО ЦЬОГО РЕПОЗИТОРІЮ

1. Закомітьте папку Website та виконайте push у свій GitHub/GitLab репозиторій.
2. Cloudflare → Workers & Pages → створити Pages project → Connect to Git.
3. Оберіть цей репозиторій. Надавайте доступ лише до потрібного репозиторію.
4. Налаштування:
   Production branch: main
   Framework preset: None
   Root directory: корінь репозиторію (порожнє значення)
   Build command: exit 0
   Build output directory: Website/dist
5. Після першого deploy відкрийте адресу *.pages.dev і перевірте всі сторінки.
6. Pages project → Custom domains → Set up a domain → onlybody.app.
   Для кореневого домену Cloudflare Pages вимагає зону в Cloudflare та її nameservers.
   Якщо DNS уже там, дотримуйтеся запропонованих налаштувань. Не змінюйте наосліп
   MX, SPF, DKIM і DMARC: вони потрібні для support@onlybody.app.
7. За бажанням додайте www.onlybody.app окремо та налаштуйте перенаправлення на основний домен.
8. Подальші push у main публікуватимуть зміни. Можна налаштувати build watch paths
   лише для Website/dist/*, щоб зміни Swift не запускали публікацію сайту.

Вихідна папка обмежена Website/dist — Swift-код, seed SQLite і Reviews не публікуються.
Репозиторій може залишатися приватним. Сторінки після публікації будуть публічними.
Не вмикайте Cloudflare Web Analytics, Zaraz чи додаткові трекери без оновлення політики.
_headers та _redirects обробляє Cloudflare Pages; звичайний локальний HTTP-сервер їх не застосовує.
Посилання email обгорнуто в <!--email_off--> … <!--/email_off-->: Cloudflare не має
замінювати їх на [email protected], бо CSP сайту забороняє JavaScript, включно зі
скриптом відновлення адреси. Зберігайте ці коментарі при редагуванні email-посилань.

АЛЬТЕРНАТИВА: РУЧНИЙ DIRECT UPLOAD

Створіть окремий Pages project типу Direct Upload і завантажте папку Website/dist.
Для ZIP покладіть ВМІСТ dist в корінь архіву (index.html має бути на верхньому рівні).
Git integration та Direct Upload — різні режими створення проєкту. Для цього
репозиторію краще одразу обрати Git integration.

ЛОКАЛЬНИЙ ПЕРЕГЛЯД

З кореня репозиторію:
  python3 -m http.server 8765 --bind 127.0.0.1 --directory Website/dist
Відкрийте http://127.0.0.1:8765/ . Для зупинки — Ctrl+C.
Внутрішні посилання використовують шляхи від кореня сайту, тому переглядайте
через HTTP-сервер, а не file://. Юридичні index.html-файли та anchors
збережені; зокрема, /privacy/index.html#youtube і /privacy/#youtube працюють.

ЗАВЕРШЕННЯ ІНТЕГРАЦІЇ ІЗ ЗАСТОСУНКАМИ

- Перевірити сторінки на *.pages.dev, потім HTTPS на onlybody.app і роботу email.
- Перевірити _headers, перенаправлення та старі HTML-адреси на Cloudflare Pages.
- Звірити Privacy Policy з фактичним хостингом, поштовим провайдером і їхніми
  налаштуваннями. Поточна політика описує Cloudflare як провайдера доставки
  та захисту сайту; вона не є доказом налаштованого Pages deployment.
- Замінити disabled Privacy/Terms у SettingsView на доступні посилання.
- Додати належне ознайомлення/прийняття політики до доступу до YouTube API features.
  Окремо визначити й реалізувати потрібний consent до необов'язкових cookies/processing.
  Поточний WKWebView звертається до YouTube до Play; сам HTML цього не змінює.
- Звірити App Store Connect Privacy labels з реальною інтеграцією YouTube.
- Перед публікацією застосунків завершити відкладений відеоаудит і фізичні перевірки.
- Коли з’являться перевірені App Store URL, замінити два disabled button.store-button
  у головній на <a> з прямими посиланнями на відповідні застосунки. Оновити
  Coming soon, FAQ і звірити публічні описи функцій та ціни. Не додавати
  вигаданих IDs або загальних посилань на пошук у магазині.
- Політика описує поточний код. При появі акаунтів, синхронізації, аналітики,
  платежів або зміні провайдера email/хостингу переглянути текст та підстави обробки.

Власник: зазначений у Privacy Policy та Terms of Use; non-trader за повідомленням власника.
Email-провайдер не встановлювався з DNS і не перевірявся; в політиці вказана категорія
email service providers. Звірте його реальні строки зберігання, DPA та міжнародні
передачі до запуску. Підстави й строки support-процесів у тексті потрібно виконувати.
Документи не є підтвердженням повного GDPR/YouTube/App Review sign-off.

ПЕРЕВІРКА ЛОКАЛЬНОГО ОНОВЛЕННЯ 26.10.2026

Виконано після скорочення текстів і змін верстки:

- Валідний sitemap XML; один H1, canonical і description на сторінку;
  унікальні IDs, усі попередні anchors збережені.

- У браузері перевірено всі 6 сторінок на 320, 390, 768 і 1280 CSS px:
  без горизонтального переповнення та зламаних зображень.
- Візуально перевірено головну на 390/768 px, OnlyWeights на 320 px,
  Privacy Policy та її розділ локальних даних на телефоні.
- Додатково перевірено всі сторінки на 640 × 450 CSS px — reflow,
  еквівалентний viewport 1280 × 900 при масштабі 200%. Реальний browser zoom
  не перемикався: його не слід вважати окремо підтвердженим цим тестом.

  у спільний CSS; нових скриптів, залежностей чи зовнішніх шрифтів немає.
- git diff --check пройдено. Код iOS, каталоги та плеєр не змінювалися;
  Xcode-тести для цього оновлення сайту не запускалися.
